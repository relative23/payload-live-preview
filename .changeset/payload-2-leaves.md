Payload 2 is no longer supported (ADR 0007, rows 25 and 30): the `payload` peer range is `^3.0.0 || ^4.0.0-0`, and a site on Payload 2 stays on the 2.x line of this package. An admin that sends `fieldSchemaJSON`, which only Payload 2 does, is refused: from the first such message on nothing of it is applied, the runtime reports `LP0504` once in every build, and a hook reports `unavailable` with the reason. Every update that is applied is merged through the server's method-override `POST`; no schema decides a field type and no collection read is started. Removed with the schema: the types `PayloadFieldSchema`, `PayloadBlockSchema` and `PayloadFieldCondition`, `fieldSchemaJSON` on `PayloadLivePreviewMessage`, `schema` on `RenderContext` and on `PayloadLivePreviewData`, the option labels of the `select` renderer, and `fieldTyping` and `populatesRelationships` on `ProtocolProfile`. `buildLivePreviewUrl()` and the config plugin read `collectionConfig` and `globalConfig`, no longer `documentInfo`. On Payload 3 or 4 nothing changes unless a custom renderer read `context.schema`, or a sender of your own added the schema: leave the field out and set `data-payload-type` on those bindings.
