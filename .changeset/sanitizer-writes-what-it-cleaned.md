`sanitizeHtml()` sanitizes with a linkedom document. It parsed into a `<template>`, cleaned `template.content` and wrote the template back, but linkedom's `content` is a copy of the template's children, so the template still held the parse: with a linkedom document every call returned its input unchanged, event handlers, `<script>`, `javascript:` URLs and `style` included. This affects every release from 1.0.0 when linkedom's document was passed to `setSanitizerDocument()` or set as the global `document`, and from 2.1.0 also when it was passed as `{ document }`, which `lexicalToHtml()` and the Astro `RichText` component's `document` prop hand on. `lexicalToHtml()` escapes the values of its built-in nodes itself, so there only markup from custom node renderers came through unsanitised. jsdom, happy-dom and browsers were not affected. The sanitizer now reads `content` once and writes the nodes it cleaned through an element of their own document; when there is no such element, or it does not end up holding them, the call throws `SanitizerEnvironmentError` instead of returning anything. With jsdom the output is unchanged, byte for byte, on the XSS corpus and 30,000 generated inputs under every policy, and so is the output in Chromium, Firefox and WebKit.
