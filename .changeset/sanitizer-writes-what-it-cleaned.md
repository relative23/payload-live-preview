`sanitizeHtml()` sanitizes with a linkedom document. It parsed into a `<template>`, cleaned `template.content` and returned the template's markup, but linkedom's `content` is a copy of the template's children, so the template still held the parse: with a linkedom document given to `setSanitizerDocument()` or set as the global `document`, every call returned its input unchanged, event handlers, `<script>`, `javascript:` URLs and `style` included. Every release from 1.0.0 to 1.8.1 did so; 1.0.0 to 1.0.3 only where a global `Node` exists, and threw a `ReferenceError` otherwise. `lexicalToHtml()` hands its output to the same sanitizer; its built-in nodes escape their own values, so there only markup from custom block renderers came through unsanitised. jsdom, happy-dom and browsers were not affected. The sanitizer now reads `content` once and writes the nodes it cleaned through an element of their own document; when there is no such element, or it does not end up holding them, the call throws `SanitizerEnvironmentError` instead of returning anything. With jsdom the output is unchanged, byte for byte, on 30,143 inputs with and without extra allowed tags and attributes, and so is the output in Chromium, Firefox and WebKit.
